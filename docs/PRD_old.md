Project Requirement Document

Overview: A Web App where a user (actor / model) can create their online portfolio easily with a few clicks. The Portfolio will basically be a single page with customizable slug, SEO friendly and generated by SSR.

Title: Spotlight (This is a working title and should be picked from a constant so that it can be updated easily)

Tech Stack: Nextjs + Supabase (Auth, DB, Storage, Functions) + Tailwind + shadcn/ui

Non-Functional Requirements:

 Technical Performance Requirements

  - Lighthouse Score: 90+ (Performance, SEO, Accessibility)
  - Page Load Time: < 2 seconds (LCP - Largest Contentful Paint)
  - Mobile Usability: 100%
  - SEO Score: 95+

  User Experience Requirements

  - Portfolio Creation Completion Rate: 70%+
  - Time to Create Portfolio: < 5 minutes
  - User Satisfaction: 4.5/5 stars
  - Mobile Usage Target: 50%+ of traffic

  Scalability & Performance

  - Mobile-First Design: Responsive design (320px+, 768px+, 1024px+)
  - Image Optimization: Next.js Image component with lazy loading
  - Bundle Optimization: Optimized bundle size
  - Critical Asset Preloading: Fonts and critical assets

  Security & Data Protection

  - Row Level Security (RLS): Comprehensive policies for all database tables
  - Authentication: Integrated Supabase auth with proper session management
  - Data Privacy: Users can only access their own data
  - Cascade Protection: Foreign key constraints with proper deletion handling

  Internationalization

  - Multi-language Support: English and Spanish with next-intl
  - Locale Persistence: Custom cookie management (1-year expiration)
  - Type Safety: TypeScript integration for translation keys
  - Future Expansion Ready: Architecture supports adding more languages

  Error Handling & Reliability

  - AI API Fallbacks: Robust fallback mechanisms for API failures
  - Rate Limit Handling: Proper handling of API rate limits
  - Image Processing Recovery: Fallback to original content on processing failures
  - User Feedback: Clear error messages and retry mechanisms
  - Zod validations for data


Functional Requirements:

- General App requirements:
    - Modern UI with responsive design: should look good and function well on all screen sizes
    - Take care of readability when naming components and variables
    - A11y and ARIA friendly - should have all the correct semantic tags and keyboard navigation
    - SEO friendly and high lighthouse score
    - Complete error handling with generic error boundary
    - Themeing: All the colors and fonts used should come out of a theme file and no static colors should be used. Also should have support for light and dark theme. All pages should follow similar pattern and similar components.

- User Management & Authentication:
    - User registration and login via Supabase auth
    - Support for Email/Password, Google and Facebook signin
    - Passord reset functionality
    - Email verification through Supabase and UI to handle it
    - Auth check should be done at server for the SSG pages and at client side for the client pages using cookie through Supabase auth

- Internationalization:
    - All URLs will be under a [locale] slug that will be auto picked from the browser locale.
    - Fallback language should be English
    - There should be a language swticher feature in the nav bar settings
    - If the user selects to change the language user the language switcher it should be saved in cookies and given preference over browser locale.
    - Create translation Json for the supported languages.
    - Only the generated portfolio pages will not be under the [locale] slug and have the exact data strings entered my the user.

- Database Schema Design
    
    - User Table
        ```sql    
            users (
                id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
                auth_user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE UNIQUE NOT NULL,
                user_role "USER_ROLE" NOT NULL DEFAULT 'GEMNERAL'
                first_name text,
                last_name text,
                gender "GENDER",
                profession text[],
                date_of_birth DATE,
                phone_number text,
                location text,
                created_at TIMESTAMP DEFAULT now(),
                updated_at TIMESTAMP DEFAULT now() 
            );
        ```
        - On new signup and entry in auth.users table, a trigger should automatically make an entry into users table
        - RLS: CURD operations can only be performed by only logged in user with same auth_user_id

    - My Pages
        ```sql
           my_pages (
                id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
                user_id UUID REFERENCES users(id) ON DELETE CASCADE NOT NULL,
                slug text UNIQUE NOT NULL,
                template_id UUID REFERENCES template(id) NOT NULL,
                page_data UUID REFERENCES page_data(id) NOT NULL
                is_published BOOLEAN DEFAULT false,
                is_featured BOOLEAN DEFAULT false,
                view_count INTEGER DEFAULT 0,
                created_at TIMESTAMP DEFAULT now(),
                updated_at TIMESTAMP DEFAULT now()
            ); 
        ```
        - RLS: CURD operation can be performed by superuser

    - Templates
        ```sql
            template(
                id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
                template_name text UNIQUE KEY DEFAULT gen_random_uuid(),
                sample_link text,
                display_image UUID REFERENCES images(id)
            )
        ```
        - RLS: CURD operation can be performed by superuser

    - Page Data
        ```sql
            page_data (
                id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
                user_id UUID REFERENCES users(id) ON DELETE CASCADE NOT NULL,
                hero_image UUID REFERENCES images(id),
                display_name text NOT NULL,
                age INTEGER,
                gender "GENDER",
                phone_number text
                bio text
            )
        ```
        - RLS: CURD operation can be performed by superuser

    - Images
        ```sql
            images (
                id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
                user_id UUID REFERENCES users(id) ON DELETE CASCADE NOT NULL,
                page_id UUID REFERENCES page_data(id) ON DELETE CASCADE,
                usage_type "IMAGE_TYPE" NOT NULL,
                storage_path text NOT NULL,
                public_url text NOT NULL,
                original_url text,
                file_type text NOT NULL,
                file_size INTEGER,
                alt_text text,
                caption text,
                sort_order INTEGER DEFAULT 0,
                created_at TIMESTAMP DEFAULT now()
            )
        ```
        - RLS: CURD operation can be performed by superuser

    enum IMAGE_TYPE: 'PROFILE', 'HERO', 'GALLERY'
    enum USER_ROLE: 'GENERAL', 'ADMIN', 'SUB_ADMIN'

    - For now keep a static constant enum of tempates: T1, T2, T3, T4
    - Corresponsing to each template there should be a separate tmplate file which is basically a container that fits all teh template data and renders it.
    - Basic idea of how the SSG will work is
    ```ts
    import Template1 from "@/templates/template1.ts"
    import Template2 from "@/templates/template2.ts"
    ....
    import TemplateNames from "@/types/enum"

    const data = fetch data from the my_page table

    switch(data.template){
        case TemplateNames.T1
            return <Template1 data={data} />

        ....
    }
    ```
